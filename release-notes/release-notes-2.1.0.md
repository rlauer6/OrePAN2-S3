# OrePAN2-S3 v2.1.0 Release Notes

**Released:** 2026-08-20  
**Author:** Rob Lauer <rclauer@gmail.com>

---

## Overview

Version 2.1.0 is a significant feature release that greatly expands
the `orepan2-s3` command-line interface with new commands, richer
deletion semantics, dry-run support, CloudFront invalidation
improvements, and better index lifecycle management. Several commands
have been renamed for clarity and consistency.

---
### Renamed Commands

The following commands have been renamed. The old names are no longer
available:

| Old Name | New Name |
|---|---|
| `download` | `download-index` |
| `create-index` | `create-site-index` |
| `create` | *(removed; use `create-site-index`)* |

### Renamed Internal Method

- `cmd_upload_index` has been renamed to `cmd_upload_site_index`. The
  CLI alias `upload-index` continues to work.

---

## New Features

### New CLI Options

The following options have been added to `orepan2-s3`:

| Option | Description |
|---|---|
| `--cli-pager` / `--no-cli-pager` | Page long output through a pager (enabled by default) |
| `--delete-all` | When a `delete` matches multiple objects, remove all of them |
| `--dryrun` | Report what would be done without making any changes |
| `--format` | Output format for informational commands (default: `json`) |
| `--invalidate-index` / `--no-invalidate-index` | Invalidate CloudFront paths after index updates (enabled by default) |
| `--save-index` | Save `02packages.details.txt.gz` to the current directory |
| `--update-site-index` / `--no-update-site-index` | Regenerate the HTML site index after package index changes (enabled by default) |
| `--upload` | Upload the generated index after creating it |

Additionally, `--profile` now takes precedence over the profile value
stored in the configuration file.

Command and option **abbreviations** are now supported — any unique
prefix is accepted.

### New Command: `list-packages`

Lists all distributions stored in the DarkPAN, grouped by distribution
name and version.

- Outputs a formatted ASCII table (requires the optional
  `Text::ASCIITable`) or JSON.
- Respects `--format json` and `--no-cli-pager`.

```
orepan2-s3 list-packages
```

### New Command: `invalidate-index` (fully implemented)

The `invalidate-index` command is now fully implemented via the new
internal `_invalidate_index()` helper. It invalidates the standard
CloudFront paths plus any paths defined in
`CloudFront.InvalidationPaths` in the config.

Requires the optional module `Amazon::API::CloudFront`.

### Automatic Index Lifecycle Management

After any operation that modifies the package index (`inject`,
`delete`), the following now happen automatically unless suppressed:

1. `02packages.details.txt.gz` is updated in S3.
2. The HTML site index (`index.html`) is regenerated and uploaded (`--update-site-index`).
3. CloudFront paths are invalidated (`--invalidate-index`).

Use `--no-update-site-index` and/or `--no-invalidate-index` to suppress individual steps.

## Enhancements

### `delete` Command — Significantly Expanded

The `delete` command now supports:

- **Name prefix matching:** pass a distribution name without `.tar.gz`
  to match all versions (e.g. `My-Package`).
- **Multi-distribution deletion:** when more than one object matches,
  `--delete-all` is required and interactive confirmation is prompted
  before any deletions occur.
- **Associated documentation removal:** documentation files under
  `docs/` generated by `create-docs` are automatically deleted
  alongside the distribution tarball.
- **Dry-run support:** pass `--dryrun` to see exactly what would be
  deleted without modifying the bucket.
- **Automatic index updates:** the package index, site index, and
  CloudFront invalidation are all updated after a delete (suppressible
  with `--no-*` flags).

```bash
# Delete a specific version
orepan2-s3 delete My-Package-1.0.0.tar.gz

# Delete all versions (with confirmation)
orepan2-s3 delete --delete-all My-Package

# Dry run
orepan2-s3 delete --dryrun My-Package
```

### `create_invalidation_batch` — Improved API

- Now accepts positional arguments `($distribution_id, $items,
  $reference)` instead of a hash.
- `CallerReference` is now auto-generated using `Data::UUID` when not supplied.
- Added input validation guards for missing or invalid `items`.

### `fetch_template` — S3 Template Support

The index template path now accepts an `s3://` URI, allowing the
Template::Toolkit template to be loaded directly from an S3 object:

```json
{ "index": { "template": "s3://my-bucket/path/to/template.tt" } }
```

### `fetch_config` — Logging

Basic configuration parameters (profile name, config file path) are
now logged at `info` level on startup.

### `cmd_create_docs` — Dynamic Author Path

`create-docs` now uses the configured `author_path` (via
`get_author_path`) instead of the hard-coded `D/DU/DUMMY` path.

### `_index_tarball` — Return Value Propagated

`_index_tarball` now returns the result of `update_index` /
`add_index`, allowing injection failures to be detected and reported
correctly.

### `OrePAN2::S3::Indexer` — New Accessors and AUTOLOAD

Added accessors to `Indexer`:
- `get_dryrun`
- `get_save_index`
- `get_update_site_index`

Added an `AUTOLOAD` stub that emits a `carp` warning when a role calls
an unsupported method, aiding debugging of role composition issues.

## Documentation Improvements

The embedded POD in `OrePAN2::S3` has been substantially revised:

- Added a `FEATURES` section summarising all major capabilities.
- All CLI options are now documented individually with types,
  defaults, and negation forms.
- All commands are documented with examples, including the expanded
  `delete` semantics.
- CloudFront pricing note updated to direct users to current AWS
  documentation rather than quoting potentially stale pricing figures.
- `=encoding utf8` declaration added.
- Configuration file example updated with `url` field placement
  correction.

---

## Build System

- `perl.mk` updated by `CPAN::Maker::Bootstrapper`: the `local`
  directory is now only added as an order-only prerequisite for `.pm`
  and `.pl` pattern rules when syntax checking is enabled
  (`syntax_on`), avoiding unnecessary rebuilds.
- `builder` script refactored: build dependency installation is now
  handled by a dedicated `install_build_deps` function that generates
  a separate `cpanfile.build` for build-time requirements, keeping
  runtime and build dependencies cleanly separated.
